# Volumetric Shaft Flip + Projected Falloff

**Date:** 2026-10-09
**Status:** Stage 1 (instrumentation) run 2026-10-09: 6 of 100 world areas in the TLAS, and
an area containing the camera was rejected (bounds distance 0, origin distance 1597).
Stage 2 pass-2 fix landed, awaiting an in-game run; pass-3 bounds cull not done.
Stage 2 verified in game. Train-lift light (`light_4014`, bound to a free-moving
lift) was self-occluded by its fixture: fixed with `r_rtVolProjEmitterBias` (24).
Stage 3/4 landed as tuned defaults: `r_rtVolProjFalloff 2` (`1/(1+x²)`, x = d/512),
`r_rtVolDirectedGain 70`. Debug mode `r_rtVolFroxelDebug 4` = blocked projected-light hits.
Stages 5-6 not started.
**Scope:** Two independent TLAS-build defects affecting every RT consumer.
Stages 1-5: volumetric in-scatter from projected lights flips between a full-screen
whiteout and near-nothing on a pure camera yaw (pass-2 distance cull). Stage 6: instance
masks and SBT routing key off `noSelfShadow` rather than a real player classification,
which breaks reflections in breakable glass. The vol pass is only where the first shows up
most loudly.

---

## Symptom

Standing inside a projected light's cone with the fixture off-screen, the whole screen
washes bright. Turn ~26° to face the fixture and the contribution all but vanishes.

---

## Evidence

Two `r_rtVolFroxelDump` captures, `game/commoutside`.

| | not looking at light | looking at light |
|---|---|---|
| `camera` | `(-1536 -1100 516)` | `(-1536 -1100 516)` |
| `forward` | `(-0.941 0.335 -0.043)` | `(-0.706 0.708 -0.020)` |
| `volLights` | 25 | 25 |

Same position. For a fixed camera position the in-scatter at any **world point** is
invariant under rotation — `rayDir` is camera→cell, so cone containment, `atten`,
`cosTheta` and the shadow ray are all unchanged. A yaw only slides a different window
over the same field. That rules out the cone test, the attenuation and the phase
function, and leaves per-frame state: the TLAS.

---

## Root cause

`VK_RT_RebuildTLAS` pass 2 ([vk_accelstruct.cpp:1453](../../neo/renderer/Vulkan/vk_accelstruct.cpp#L1453))
re-adds static geometry that portal/frustum culling dropped from `viewEntitys`. Two
defects make it a no-op for world geometry:

| # | Defect | Detail |
|---|---|---|
| 1 | Radius sized for GI rays only | `distCullSq = (2 * r_rtGIRadius)²` = **256²**. Vol shadow rays reach `r_rtVolMaxDist` (512) + light distance (341) ≈ **850**. `r_rtReflectionDistance` is **2500**. |
| 2 | Cull uses `parms.origin`, which is `(0,0,0)` for every world area | `_area<N>` entityDefs never get an origin assigned ([RenderWorld_load.cpp:714](../../neo/renderer/RenderWorld_load.cpp#L714)); the real extent is in `referenceBounds`. At `|camPos| = 1958` every area fails the 256-unit test. |

Net: the TLAS holds only this frame's portal-visible set. Turn away from the light and
its mounting wall, door frame and intervening structure leave the acceleration
structure; every froxel in the 2363-unit cone then passes its occlusion test against
nothing, at `r_rtVolDirectedGain = 60`.

Corroborated in reflections: off-screen props do appear, and drop out "further away" —
that is pass 2's 256 units for static and `r_rtNearDynRadius = 512` for dynamic. The
missing world BSP goes unnoticed without a mirror facing open space.

Secondary (real, not the headline): the projected-light branch at
[vol_froxel_fill.comp:191](../../neo/renderer/glsl/vol_froxel_fill.comp#L191) is
`atten = 1 - alongCone / 2362.8` — flat across a 512-unit grid. No inverse square, no
beam spread, no `light_start` near plane, and the cone half-angle circumscribes the
rectangular projection pyramid.

---

## Ordering

Stage 3 must not run before stage 2. Tuning the gain now would absorb the occlusion
error, and undoing it later costs a second pass. Expect the fixed image to be **darker
overall but with the shafts more legible** — shadowed fog gains silhouette structure
(grate bars, door frames, fan blades) that a wash has none of. Gain may need to go
*up* from 60, not down.

## 4. Projected-light falloff

`atten` for `lightType` 1 and 2 needs a distance term. A true `1/r²` crushes the far
end of the beam, which is the part worth keeping, and Doom 3's own projected lights do
not use one — the GL path takes falloff from the projection's falloff image along S
plus the natural spread of the pyramid. Compare side by side before choosing:

| Option | Cost | Note |
|---|---|---|
| (a) Softened `1/(1 + (d/d0)²)`, `d0` from the light's own reach | free | Near field bounded, far field survives; one tuning knob |
| (b) Sample the light's falloff image | one texture fetch | Mapper-authored shape, no tuning |

Also in scope: `light_start` near plane (cells between apex and start should be dark),
and the circumscribing-cone half-angle at
[vk_gi.cpp:1954](../../neo/renderer/Vulkan/vk_gi.cpp#L1954).

**Check:** screenshot pairs at the same spot across both options plus current, at
matched gain.

## 6. Give the player a dedicated instance mask bit

Second TLAS-build defect, independent of the pass-2 radius above. Both `inst.mask` and
`instanceShaderBindingTableRecordOffset` are derived from `parms.noSelfShadow`
([vk_accelstruct.cpp:1268](../../neo/renderer/Vulkan/vk_accelstruct.cpp#L1268)), but that
flag is not player-specific. `BrittleFracture` sets it
([BrittleFracture.cpp:183](../../neo/game/BrittleFracture.cpp#L183)), as do `PlayerIcon`,
`Projectile`'s secondModel and `Weapon`.

**Symptom:** reflections in breakable glass are wrong. Repro — the window at the Pinky
introduction in Administration.

Glass is broken two ways, both from being treated as the player:

| # | Mechanism |
|---|---|
| 1 | **Invisible to the glass probe.** The probe traces cull mask `0xFE` ([reflect_ray.rgen:242](../../neo/renderer/glsl/reflect_ray.rgen#L242)); glass carries `0x01`; `0x01 & 0xFE == 0`. The pass whose job is finding glass cannot see breakable glass. |
| 2 | **Shaded as player body.** SBT offset 2 routes the main reflection ray to `player_reflect.rchit`, which returns opaque diffuse with `transmittance = 0.0`, so glass reflects as a solid surface instead of transmitting. |

| File | Change |
|---|---|
| `vk_accelstruct.cpp` | Reserve mask bit `0x02` for `idPlayer` + head geometry only; drive `inst.mask`, SBT offset and `VK_MAT_FLAG_PLAYER_BODY` from that, not from `noSelfShadow` |
| `reflect_ray.rgen` | Glass probe mask `0xFE` → exclude the new player bit only |
| `shadow_ray.rgen`, `gi_ray.rgen`, `gi_probe_trace.rgen` | Same substitution — makes the first-person-body exclusions precise instead of approximate (see `20261001_see_first_person_player_model.md`) |

Identifying the player at TLAS-build time is the open question: `idRenderEntityLocal` has no
"is player" bit today, so this likely needs a new `renderEntity_t` flag set by `idPlayer`,
with the demo read/write path updated alongside it.

**Check:** the Administration window — glass probe should fire on it, and the reflection
should transmit rather than read as a solid wall. Confirm the player still appears correctly
in mirrors, since the SBT routing is what puts them there.

## 7. Vertex-cache allocation churn (CPU stall)

Not a TLAS defect; found chasing a frame-rate drop near `commoutside_railarc.prt` (28
emitters). Same drop with RT off. Step 0 (per-caller counters, `VK VC SITES` under
`r_vkRTProfile 1`) is landed and run.

**Cause:** every non-`TAG_TEMP` block goes through `VK_VertexCache_Alloc`
([vk_buffer.cpp:224](../../neo/renderer/Vulkan/vk_buffer.cpp#L224)): 2× `vkCreateBuffer` +
`vkAllocateMemory` (device + staging), map/memcpy/unmap, a copy into the shared upload batch;
staging freed at the next flush, device buffer destroyed via the garbage ring. Uploads are
already one submit + one fence wait ([vk_instance.cpp:616](../../neo/renderer/Vulkan/vk_instance.cpp#L616)),
so the remaining cost is per-block object churn: ~0.55-0.6 ms per block, size-independent.

| Scene (RT off) | `VK VC SITES` count/KB/ms | `vcAlloc` | `drain`+`upload` |
|---|---|---|---|
| Railarcs, particles on | `ambient.cont` 64/206/36, `ambient.cached` 12/94/6.7, `shadowVP.other` 3/67/1.9 | 79 / 45 ms | 23 + 23 ms |
| Firefight, particles off | `ambient.cached` 9-16/150-258/5-9, `shadowVP.other` 4-5/~140/~3, `ambient.static` 5-9/4-26/3-5 | 14-26 / 8-17 ms | 5-7 + 5-8 ms |

Firefight CPU frame ~33 ms, ~25-30 ms of it churn. Cached/skinned and shadow blocks dominate
there, so a continuous-only transient ring (old option A) is not enough.

**Decision:** sub-allocate (B-full) in four chunks. Transient ring (A) only if a re-profile
still shows particle scenes heavy. Content-side cap (C) rejected: hides one scene.

## 7 design

| Part | Design |
|---|---|
| Chunks | DEVICE_LOCAL `VkBuffer`, 32 MB (matches `r_vertexBufferMegs`), usage VERTEX \| INDEX \| TRANSFER_DST \| AS_BUILD_INPUT \| DEVICE_ADDRESS. First chunk at init, grow on demand, oversize request gets a dedicated chunk, allocation failure falls back to today's per-block path. |
| Sub-allocator | Per-chunk free list sorted by offset, best-fit, coalesce on free. 64-byte alignment (covers vertex, index and AS-input requirements). |
| Block handle | `vkBufferData_t` = {chunk, offset, size}. `VK_VertexCache_GetBuffer` returns `chunk->buf` + offset; every consumer already adds the offset. |
| Free | Same per-frame-slot garbage ring; `VK_Buffer_DrainGarbage` returns the range after the slot's fence. |
| Staging | One persistently mapped HOST_VISIBLE\|COHERENT ring (16 MB). Bump-allocate, record `vkCmdCopyBuffer`, reset after `VK_FlushPendingUploads`. Full → flush then reset. Oversize → dedicated staging as today. |
| Accounting | Keep `s_bufferLive*`; add free bytes, largest free block, chunk count to the `r_vkLogBufferGarbage` line. |

## 7.4 Drop the per-frame submit + wait (conditional)

Only if `upload` is still ≥ ~2 ms after 7.2. Record buffer copies at the start of the frame
command buffer with a barrier (TRANSFER_WRITE → VERTEX_ATTRIBUTE_READ \| INDEX_READ \|
AS_BUILD_INPUT_READ \| SHADER_READ); staging ring becomes per frame slot; images keep the old
batch; uploads outside a frame (level load) keep the old path.
