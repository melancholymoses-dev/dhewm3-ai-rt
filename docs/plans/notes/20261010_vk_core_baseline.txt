Bug found by this capture
-------------------------
Window 1 read p50 2.563 / p95 4.287 while windows 2-18 all read p50 ~4.27. The 2.563 is the
0.667-scale value from before the setting changed: a partial window survived profiling being
toggled off, because PushFrame is unreachable while off and nothing cleared s_windowCount.
Fixed in VK_Prof_BeginFrameSlot (discard the partial window on an off->on transition or a
window-size change). Treat the first window after any cvar change in earlier logs as suspect.

Next capture
------------
The only capture recipe. r_vkRTProfileGroups is a console filter and is always left at 63;
every group is collected and written to the CSV regardless, so analysis never needs it.

  com_fixedTic 1
  r_vkRTProfileCSV <scenario>.csv
  r_vkRTProfileWindow 60
  r_vkRTProfile 1

With a CSV open the console block is suppressed (one heartbeat line per window) and
r_vkRTProfileSpikeMs is ignored; set it only when capturing without a file.

Then, before reading any individual frame:

  python tools/vk_profile_report.py <scenario>.csv
  python tools/vk_profile_report.py after.csv --baseline before.csv   # per-stage deltas
